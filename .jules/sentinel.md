## 2026-10-03 - [Path Traversal in Static File Handler]
**Vulnerability:** A path traversal vulnerability existed in the static file serving logic of `server.js` due to relying on simple prefix matching (`startsWith(PUBLIC_DIR)`) on decoded path names. This allowed an attacker to use URL-encoded sequences (`%2E%2E%2F`) to bypass the check and access out-of-bounds files if the target path also shared a partial directory prefix (e.g., escaping `public` to access `public-secret`).
**Learning:** In Node.js native routing, `new URL()` does not normalize URL-encoded path separators. Calling `decodeURIComponent()` on `url.pathname` afterwards activates traversal elements (`../`), effectively bypassing basic `.startsWith()` checks. Additionally, if the root directory lacks a trailing slash, prefix checks are susceptible to partial directory name exploits.
**Prevention:** Always enforce path boundaries using `path.relative(ROOT_DIR, targetPath)` and verifying that the resulting relative path does not start with `..` and is not absolute. Furthermore, return generic `404 Not Found` errors instead of `403 Forbidden` for out-of-bounds requests to prevent information leakage regarding directory structure.
