## 2026-08-30 - Path Traversal bypass via omit separator
**Vulnerability:** A critical path traversal vulnerability was discovered in `server.js`'s static file handler. Although `decodeURIComponent(new URL(...).pathname)` was used, the authorization check `!filePath.startsWith(PUBLIC_DIR)` could be bypassed. For instance, if `PUBLIC_DIR` is `/app/public`, a requested file in a sibling directory named `/app/public-secrets` would pass the check because `/app/public-secrets`.startsWith(`/app/public`) is true, despite escaping the intended directory bound.
**Learning:** `new URL()` does not normalize URL-encoded path separators (e.g., `%2E%2E%2F`). When combined with a flawed `startsWith` boundary check (which only does a raw string prefix check and ignores path segment boundaries), attackers can traverse path boundaries.
**Prevention:** Always use `path.relative(baseDir, targetDir)` and ensure the returned relative path doesn't start with `..` nor is absolute. Do not rely on `startsWith()` for directory containment.
