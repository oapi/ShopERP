## 2024-05-18 - Path Traversal bypass via missing trailing slash and late decodeURIComponent
**Vulnerability:** Node.js file server uses `filePath.startsWith(PUBLIC_DIR)` after applying `decodeURIComponent` to `url.pathname` on paths parsed by `new URL()`. The `startsWith` check can be bypassed by traversing to a sibling directory whose name starts with the public directory name (e.g., `/public_secret`). The `new URL()` initially decodes `%2f` but a malicious request like `/..%2fpublic_secret` will leave `%2f` intact through URL parsing, and the subsequent `decodeURIComponent` turns it into `/../public_secret`. When joined with `/app/public`, it becomes `/app/public_secret`. `filePath.startsWith('/app/public')` returns `true` because `/app/public_secret` begins with `/app/public` as a string, completely bypassing the directory boundary limitation.
**Learning:** `startsWith` on paths without a trailing directory separator is unsafe and allows prefix matching. Also, applying `decodeURIComponent` after `new URL` parsing can reintroduce un-normalized traversal components like `..`.
**Prevention:** Use robust relative path checking (`path.relative(PUBLIC_DIR, filePath)`) and ensure it does not begin with `..` or is an absolute path. Alternatively, explicitly enforce the boundary by ensuring `filePath` matches the directory exactly or starts with `PUBLIC_DIR + path.sep`. Avoid manually decoding parts of the URL that could change structure without immediately re-normalizing.
