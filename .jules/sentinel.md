## 2024-10-04 - Fix Path Traversal Vulnerability
**Vulnerability:** A path traversal vulnerability existed due to weak boundary checking in the static file serving logic. Using `filePath.startsWith(PUBLIC_DIR)` after appending user-supplied paths did not adequately prevent traversal if the decoded sequence contained active directory ascensions, or if the `PUBLIC_DIR` was a prefix for another legitimate sibling directory (e.g., `public-secret`).
**Learning:** `new URL()` does not normalize URL-encoded path separators (`%2E%2E%2F`). If `decodeURIComponent()` is called on `url.pathname` afterwards, the encoded sequences become active traversal elements (`../`), which bypasses simple prefix matching like `startsWith()`. Returning `403 Forbidden` for an out-of-bounds request can also leak the existence of protected directories.
**Prevention:** Use `path.relative()` to correctly check for directory boundary escapes (e.g., `relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`). Instead of `403 Forbidden`, intentionally return a generic `404 Not Found` for invalid or out-of-bounds requests to prevent information leakage about the server's internal directory structure.
