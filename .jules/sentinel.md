## 2024-05-15 - [CRITICAL] Fix Path Traversal Vulnerability in Native HTTP Server
**Vulnerability:** A path traversal vulnerability existed in the static file serving logic in `server.js`. The boundary check `filePath.startsWith(PUBLIC_DIR)` was flawed because if `PUBLIC_DIR` lacks a trailing slash (e.g., `/app/public`), a requested path resolving to a sibling directory like `/app/public-secret` (achieved via URL-encoded `../`) would bypass the `startsWith` check, exposing arbitrary files on the filesystem.
**Learning:** In Node.js native routing, `new URL()` preserves URL-encoded sequences like `%2E%2E`. When subsequently decoded and joined with `path.join`, these become active traversal elements (`../`). Using `.startsWith()` for boundary validation is insufficient and inherently vulnerable to partial directory name matches.
**Prevention:** Always use `path.relative(ROOT_DIR, requestedPath)` for final boundary validation in custom static file servers. Verify that the resulting relative path does not start with `..` and is not an absolute path to ensure strict containment within the intended directory.
