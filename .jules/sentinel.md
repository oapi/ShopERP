## 2024-05-18 - Path traversal via url encoding bypassing startsWith boundary checks
**Vulnerability:** A critical path traversal vulnerability existed in static file serving where `decodeURIComponent` was used on the requested path, allowing `%2E%2E%2F` sequences to be evaluated as `../`. Because the `PUBLIC_DIR` string lacked a trailing slash, boundary verification using `filePath.startsWith(PUBLIC_DIR)` could be bypassed if the user requested a path like `/../public-secret/secret.txt`.
**Learning:** `startsWith` is insufficient and vulnerable to partial directory name matches and path normalization nuances when enforcing directory bounds.
**Prevention:** Always use `path.relative(PUBLIC_DIR, filePath)` and check if it resolves to a string starting with `..` or `path.isAbsolute()` to ensure the file path stays strictly within the intended directory. Furthermore, returning a generic `404 Not Found` error instead of `403 Forbidden` prevents information leakage about directory structures or file existence.
