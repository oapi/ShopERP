## 2026-10-02 - Path Traversal via Partial Directory Matching
**Vulnerability:** The application attempted to prevent path traversal by checking `filePath.startsWith(PUBLIC_DIR)`. However, it was vulnerable to partial directory matching because `PUBLIC_DIR` did not have a trailing slash (e.g., `/app/public`). An attacker could access files in a sibling directory named similarly, such as `/app/public-secret`, by requesting `/%2e%2e%2fpublic-secret/secret.txt`. `new URL()` processes the string, but `decodeURIComponent` acts afterward allowing active traversal sequences.
**Learning:** `startsWith` is insufficient for directory boundary checks in Node.js when the base path lacks a trailing slash, as it allows prefix matches. Additionally, returning a `403 Forbidden` leaks the existence of invalid paths.
**Prevention:** Always use `path.relative(BASE_DIR, resolvedPath)` and ensure the result does not start with `..`, does not equal `..`, and is not an absolute path. Return a generic `404 Not Found` to avoid leaking path existence.
