## 2025-02-27 - Path Traversal bypass via URL Encoding and Missing Trailing Slash
**Vulnerability:** A path traversal vulnerability existed in static file serving due to checking boundaries using `filePath.startsWith(PUBLIC_DIR)`. This was vulnerable because `PUBLIC_DIR` lacked a trailing slash, allowing sibling directory access (e.g., `public-secret`), and `new URL()` in Node.js does not normalize URL-encoded path separators (`%2e%2e%2f`), bypassing the basic prefix check after `decodeURIComponent()`.
**Learning:** `startsWith()` prefix matching is fundamentally flawed for path validation unless strictly checking against a trailing slash. Additionally, URL-encoded path characters (`%2F`, `%2E`) remain encoded after `new URL()`, bypassing validation if decoded later. Always use robust path resolution checking.
**Prevention:** Always use `path.relative(baseDir, targetDir)` and ensure it does not start with `..` (or equal `..`) or resolve to an absolute path to strictly enforce directory boundaries. Also return a 404 instead of 403 to prevent information leakage about the server directory structure.
