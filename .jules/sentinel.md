## 2024-05-24 - [Path Traversal in Static File Handler]
**Vulnerability:** The static file handler in `server.js` was vulnerable to path traversal attacks when serving files. An attacker could use `%2e%2e%2f` (`../` encoded) in the URL path to escape the `PUBLIC_DIR` directory and access arbitrary files on the filesystem. This is because `url.pathname` preserves URL-encoded characters (like `%2F`), and `decodeURIComponent(url.pathname)` creates the `../` traversal sequence *after* the initial `startsWith` directory boundary check. The `startsWith` check itself is also flawed if the directory name lacks a trailing slash (e.g. `public` vs `public-secret`).
**Learning:** `new URL()` in Node.js does not normalize URL-encoded path separators (e.g., `%2E%2E%2F`). If `decodeURIComponent()` is called on `url.pathname` afterwards, the encoded sequences become active traversal elements (`../`), which bypasses simple prefix matching like `startsWith()`. This enforces the requirement to use `path.relative(PUBLIC_DIR, filePath)` for final boundary validation.
**Prevention:** Use `path.relative(PUBLIC_DIR, filePath)` and check if the relative path escapes the directory (e.g., `relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`) to enforce strict boundaries.
