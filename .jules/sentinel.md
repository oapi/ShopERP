## 2026-09-23 - Path Traversal bypass with decodeURIComponent and startsWith

**Vulnerability:** Path traversal (arbitrary file read) was possible because the static file path check (`!filePath.startsWith(PUBLIC_DIR)`) could be bypassed. `decodeURIComponent` normalized URL encoded path traversal vectors (e.g. `%2E%2E%2F` to `../`), and a lack of explicit path boundary testing allowed those segments to traverse beyond the `PUBLIC_DIR` after standard path matching, allowing the server to serve sensitive server files like `server.js` or `data/shop.db`.
**Learning:** `new URL()` in node's native routing doesn't normalize URL-encoded path separators. If `decodeURIComponent()` is applied, these sequences become active `../` traversals, easily bypassing simple prefix matching like `startsWith()`. Returning `404 Not Found` for invalid paths instead of `403 Forbidden` prevents information leakage about whether files exist out of bounds.
**Prevention:** Use `path.relative()` to verify boundaries and explicitly check if it escapes the directory (e.g., `relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`) to enforce strict boundaries. Return generic `404 Not Found` for out of bounds files.
