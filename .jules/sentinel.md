## 2025-01-20 - Fix timing attack vulnerability in authentication
**Vulnerability:** The authentication endpoint previously combined username and password checks in a single SQL query (`SELECT ... WHERE username = ? AND password_hash = ?`). This logic exits early or takes varied time depending on the success of the password match, making the endpoint vulnerable to timing attacks that could reveal valid user accounts or password hashes.
**Learning:** Checking hashes in the database via string comparison exposes differences in query execution time. Also, checking for the user first and returning early before hashing the password introduces a username enumeration vulnerability since password hashing takes noticeable time.
**Prevention:** Always compute the hash unconditionally. Then fetch the user record by unique identifier (e.g. `username`), and compare the submitted password hash against the stored `password_hash` using Node's `crypto.timingSafeEqual` with equal-length buffers. Use a dummy `crypto.timingSafeEqual` if the user is not found. This ensures the comparison executes in constant time, regardless of validity or existence of the user.
