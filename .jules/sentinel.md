## 2024-10-15 - Fix Path Traversal via Partial Directory Match
**Vulnerability:** The static file serving route used `filePath.startsWith(PUBLIC_DIR)` to verify that requested files were within the public directory (`/app/public`). Because `PUBLIC_DIR` lacked a trailing slash, an attacker could access a sibling directory (e.g., `/app/public-secret`) using a URL like `/../public-secret/file.txt`, since `/app/public-secret` starts with `/app/public`.
**Learning:** `startsWith()` on directory paths is vulnerable to partial directory name matches if the path lacks a trailing slash. This is a common and subtle path traversal vector in Node.js applications.
**Prevention:** Always use `path.relative(baseDir, targetDir)` and strictly check if the resulting relative path attempts to traverse up (`startsWith('..')`, `=== '..'`, or `path.isAbsolute()`) instead of relying on naive string prefix matching for security boundaries. Additionally, failing securely by returning 404 instead of 403 prevents directory structure enumeration.
