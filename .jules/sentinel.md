## 2024-10-06 - Path Traversal bypass via `decodeURIComponent`
**Vulnerability:** A directory traversal attack was possible due to flawed path validation when serving static files. The codebase used `filePath.startsWith(PUBLIC_DIR)` after applying `decodeURIComponent` to the URL.
**Learning:** Node.js native routing using `new URL()` does not automatically normalize URL-encoded path separators (e.g., `%2E%2E%2F` or `..%2f`). If `decodeURIComponent()` is called on `url.pathname` afterwards, the encoded sequences become active traversal elements (`../`). Using simple string prefix checks like `startsWith()` on the resulting path fails to properly validate directory bounds because `path.join` resolves `../` sequences back into the directory tree, potentially exposing sibling directories or arbitrary system files if `../` sequences successfully bypass the prefix check.
**Prevention:** Always use `path.relative()` to validate file path boundaries, and explicitly check if the relative path escapes the expected root directory (e.g., `relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`). Additionally, returning a generic 404 instead of 403 prevents information leakage about the existence of files outside the designated public directory.
