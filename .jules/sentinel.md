## 2026-08-16 - Path Traversal via Prefix Bypass & URL Encoding
**Vulnerability:** A critical path traversal vulnerability existed in the static file serving logic in `server.js` due to a flawed prefix check (`filePath.startsWith(PUBLIC_DIR)`). An attacker could bypass this by requesting paths like `/%2E%2E%2Fpublic_secret%2Fabc.txt`.
**Learning:** `new URL()` does not normalize URL-encoded traversal sequences (like `%2E%2E`). When `decodeURIComponent()` is subsequently called on the `pathname`, these sequences resolve back into active directory traversals (`../`). When concatenated via `path.join`, this can construct paths like `/app/public_secret/abc.txt` which coincidentally start with the prefix string `/app/public`, successfully bypassing `startsWith()` checks.
**Prevention:** Never rely on string prefix matching (e.g., `startsWith`) for directory boundary checks. Always use `path.relative(baseDir, resolvedPath)` and verify that the resulting relative path is not absolute and does not traverse upwards (i.e., does not equal `..` and does not start with `..` + `path.sep`).
