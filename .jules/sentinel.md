## 2025-02-18 - Path Traversal via Partial Directory Match
**Vulnerability:** A path traversal vulnerability existed in the static file handler. An attacker could access files outside the `public` directory if the target directory's name started with `public` (e.g., `public-secret`).
**Learning:** `new URL()` does not decode URL-encoded path separators (like `%2E%2E%2F`). When `decodeURIComponent` is subsequently called on the pathname, these separators become active traversal characters (`../`). The boundary check relied on `filePath.startsWith(PUBLIC_DIR)`. Since `PUBLIC_DIR` was `/app/public` (no trailing slash), a resolved path like `/app/public-secret/secret.txt` incorrectly passed the `startsWith` check.
**Prevention:** Never rely on `startsWith()` for path boundary validation unless the base directory string includes a trailing slash or is strictly enforced. Instead, compute the relative path using `path.relative(baseDir, filePath)` and ensure it does not start with `..` and is not absolute (`path.isAbsolute(relPath)`).
