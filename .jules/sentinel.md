## 2026-08-17 - Sibling Directory Path Traversal
**Vulnerability:** Node.js native server path resolution in `server.js` was vulnerable to sibling directory traversal because it used `filePath.startsWith(PUBLIC_DIR)` for boundary checking. Since `new URL()` does not normalize URL-encoded `..` sequences, `decodeURIComponent()` subsequently converted them to literal `..`, which `path.join()` resolved. If `PUBLIC_DIR` was `/app/public` and requested path was `/app/public-sibling/secret.txt`, `.startsWith('/app/public')` returned `true`, bypassing the check.
**Learning:** `startsWith` is insufficient and actively dangerous for path boundary checks because sibling directories sharing the same prefix will falsely pass. Node.js `new URL()` also does not decode or resolve `%2e%2e` natively.
**Prevention:** Always use `path.relative(baseDir, resolvedPath)` and check that the relative path does not equal `'..'`, does not start with `'..' + path.sep`, and is not an absolute path.
