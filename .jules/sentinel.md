## 2026-09-27 - Path Traversal Vulnerability in Static File Serving
**Vulnerability:** A path traversal vulnerability existed in the static file serving logic due to the interaction of `decodeURIComponent`, `path.normalize`, and an insecure `startsWith(PUBLIC_DIR)` boundary check. If `PUBLIC_DIR` doesn't have a trailing slash (e.g. `/app/public`), a request to `/../public-secret/secret.txt` normalizes to `/app/public-secret/secret.txt`, which successfully matches `.startsWith('/app/public')` and bypasses the check, granting access to sibling directories. In addition, URL encoded sequences like `%2E%2E%2F` bypassed the boundary check if `new URL` is used and followed by `decodeURIComponent`, exposing arbitrary files.
**Learning:** `new URL()` does not normalize URL-encoded path separators. Decoding the pathname *after* parsing allows encoded traversal sequences (`../`) to become active. Using `startsWith` without an explicit trailing slash for directory boundaries is fundamentally flawed because it allows partial directory name matches.
**Prevention:** Always use `path.relative(BASE_DIR, targetPath)` and enforce strict boundary checking (`relativePath !== '..'`, `!relativePath.startsWith('..' + path.sep)`, and `!path.isAbsolute(relativePath)`). Additionally, fail securely by returning a generic 404 Not Found instead of 403 Forbidden to prevent information leakage about internal server paths.
