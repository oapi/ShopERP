## 2026-10-13 - Path Traversal in Static File Serving
**Vulnerability:** A path traversal vulnerability existed in `server.js` because `filePath.startsWith(PUBLIC_DIR)` was used to validate paths, but `PUBLIC_DIR` did not end with a trailing slash (`/`). This allowed a partial directory name match to pass the boundary check (e.g., accessing `/app/public-secret` when the valid path prefix was `/app/public`). Additionally, URL-encoded path separators (`%2e%2e%2f` for `../`) became active traversal sequences after being decoded by `decodeURIComponent()`.
**Learning:** In Node.js native routing, decoding `url.pathname` creates traversal capabilities, and using `startsWith` for directory boundary validation without a trailing slash is prone to partial matches.
**Prevention:** Always use `path.relative(DIRECTORY, targetPath)` and ensure the returned relative path does not escape the boundary (e.g., `rel === '..' || rel.startsWith('..' + path.sep) || path.isAbsolute(rel)`).
