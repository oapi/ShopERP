## 2024-05-15 - [Path Traversal in Node.js Static Server]
**Vulnerability:** A path traversal vulnerability existed in `server.js` due to the use of `filePath.startsWith(PUBLIC_DIR)`. While this checks if the absolute resolved path starts with the public directory path (e.g., `/app/public`), it fails if the public directory name is a prefix of another directory name (e.g., `/app/public-secret`). Furthermore, URL-encoded path traversal sequences (`%2E%2E%2F`) decoded *after* `URL` parsing bypass simple prefix matching, resulting in the ability to read arbitrary files via partial directory name matching.
**Learning:** `String.prototype.startsWith()` is insufficient and dangerous for verifying path boundaries, especially when the base directory string does not end with a trailing slash (`path.sep`). Attackers can craft payloads accessing sibling directories that share the same string prefix. Additionally, `decodeURIComponent()` on `url.pathname` creates active traversal elements (`../`) that must be bounded securely.
**Prevention:** Always use `path.relative(baseDir, targetDir)` and verify that the resulting relative path does not escape the base directory (e.g., `relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`).
