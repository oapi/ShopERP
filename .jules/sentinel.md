## 2024-05-15 - [Path Traversal via Sibling Directory Bypass]
**Vulnerability:** A path traversal vulnerability existed in the static file serving logic due to the use of `.startsWith()` for boundary validation (`!filePath.startsWith(PUBLIC_DIR)`). An attacker could supply URL-encoded sequences (`%2e%2e/public_secrets`) which bypass the initial `new URL()` normalization but become active traversal elements upon decoding. Crucially, even if resolved to a directory OUTSIDE the target (like `/app/public_secrets`), if that directory name starts with the target directory name (`/app/public`), `.startsWith()` returns true, bypassing the check (Sibling Directory Bypass).
**Learning:** `new URL()` does not normalize URL-encoded path separators, and `.startsWith()` is insufficient for path boundary validation because it is susceptible to partial string matches (sibling directory attacks).
**Prevention:** Always use `path.relative(baseDir, resolvedPath)` for boundary validation and ensure the result does not equal '..', start with '..' + path.sep, or resolve to an absolute path.
