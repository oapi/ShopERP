## 2024-05-18 - Fix Path Traversal in Static File Handler
**Vulnerability:** Path traversal in static file handler allowing access to files outside `PUBLIC_DIR` via URL encoded paths like `/%2e%2e/data/shop.db`.
**Learning:** `decodeURIComponent(url.pathname)` decodes encoded traversal sequences (`%2e%2e` -> `..`), and then `path.normalize(path.join(PUBLIC_DIR, filePath))` creates an absolute path that is outside `PUBLIC_DIR`. Because `startsWith(PUBLIC_DIR)` is used before this normalization (or is bypassed if not absolute), it does not protect against these sequences correctly. Specifically, `filePath = pathname === '/' ? '/index.html' : pathname; filePath = path.normalize(path.join(PUBLIC_DIR, filePath));` causes the vulnerability because `startsWith` is called on the resolved path which actually *does* start with `PUBLIC_DIR` string if `PUBLIC_DIR` doesn't end with a slash and the escaped directory name starts with `public`. Wait, `startsWith(PUBLIC_DIR)` was called on the `filePath`. Wait, if `PUBLIC_DIR` is `/app/public`, and `filePath` is `/app/public-secret/secret.txt`, `filePath.startsWith('/app/public')` is true. Also `/%2e%2e` gets decoded to `/..`.
**Prevention:** Always use `path.relative(PUBLIC_DIR, resolvedPath)` and ensure the result does not start with `..` and is not absolute to strictly verify that the resolved path is within the intended directory.
