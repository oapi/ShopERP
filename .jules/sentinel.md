## 2026-09-20 - Enforce strict path boundaries to prevent partial match traversal
**Vulnerability:** Path traversal (Information Exposure). The application verified file paths using `startsWith(PUBLIC_DIR)` for static file serving. Because `PUBLIC_DIR` did not end in a trailing slash, it allowed accessing files in identically prefixed sibling directories (e.g., `/app/public-secret`). Furthermore, `decodeURIComponent` in the URL parsing could expose the `../` pattern leading to boundary escapes.
**Learning:** `startsWith` on a directory path without a trailing slash is insufficient for boundary enforcement. `URL` decoding happens after path construction but string traversal checks do not normalize the resulting path.
**Prevention:** Always use `path.relative(base, target)` to evaluate out-of-bound file accesses, and explicitly check if the relative path starts with `..` or is absolute. Return generic `404 Not Found` for traversal attempts rather than `403 Forbidden` to prevent revealing internal structural information.
