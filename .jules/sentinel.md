## 2024-09-25 - Path Traversal bypass via URL encoding
**Vulnerability:** In `server.js`, a path traversal vulnerability exists when serving static files. The path boundary validation `!filePath.startsWith(PUBLIC_DIR)` is performed after `decodeURIComponent(url.pathname)` and `path.normalize()`. However, `url.pathname` decoded with `%2E%2E%2F` becomes `../`, which `path.normalize` resolves, but the resulting `filePath` could still start with `PUBLIC_DIR` if there is a directory like `public-secret` that shares the same prefix `public`. This bypasses the validation.
**Learning:** `startsWith` is not a reliable way to check for path boundaries. It's susceptible to prefix-matching bugs (e.g., `/app/public-secret` starts with `/app/public`). Furthermore, URL decoding should happen before normalization to ensure the normalized path is evaluated against traversal attempts.
**Prevention:** Use `path.relative(baseDir, targetDir)` and verify that the relative path does not start with `..` and is not absolute to correctly enforce boundaries.
