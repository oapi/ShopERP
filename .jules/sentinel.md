## 2026-09-30 - Fix Path Traversal in Static File Server
**Vulnerability:** The static file server used `path.normalize(path.join(PUBLIC_DIR, pathname))` and then validated bounds using `filePath.startsWith(PUBLIC_DIR)`. Because `PUBLIC_DIR` did not end in a trailing slash (`/app/public`), it was vulnerable to partial directory match exploits. An attacker could request `..%2fpublic-secret/secret.txt` which resolves to `/app/public-secret/secret.txt`, effectively bypassing the `startsWith` check.
**Learning:** In Node.js native routing, `new URL()` does not normalize URL-encoded path separators. If `decodeURIComponent()` is called afterwards, encoded sequences become active traversal elements. Relying solely on `startsWith()` for boundary checks without a trailing slash is insufficient.
**Prevention:** Always use `path.relative(PUBLIC_DIR, filePath)` and ensure the relative path does not escape the directory (e.g., `relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`). Additionally, return a generic `404 Not Found` rather than `403 Forbidden` to prevent information leakage about the server's internal directory structure.
