## 2025-02-17 - [CRITICAL] Path Traversal Sibling Directory Bypass
**Vulnerability:** A path traversal vulnerability existed in static file routing (`server.js`) due to the use of `startsWith()` for prefix checking (e.g., `if (!filePath.startsWith(PUBLIC_DIR))`). By URL-encoding `../` as `%2e%2e%2f` and placing it *after* the `new URL()` normalization but *before* `path.normalize()`, an attacker could traverse up to the parent directory and then down into a sibling directory that shares the same prefix (e.g., `/public-secret/secret.txt`). `startsWith` incorrectly allowed this because `/app/public-secret` starts with `/app/public`.
**Learning:** `new URL()` does not normalize URL-encoded path separators (e.g., `%2E%2E%2F`). If `decodeURIComponent()` is called on `url.pathname` afterwards, the encoded sequences become active traversal elements (`../`), which bypasses simple prefix matching like `startsWith()`. This enforces the requirement to use `path.relative()` for final boundary validation.
**Prevention:** Never use `String.prototype.startsWith()` for path boundary validation. Always use `path.relative(baseDir, resolvedPath)` and ensure the result does not equal `..`, start with `..` + `path.sep`, or resolve to an absolute path.
