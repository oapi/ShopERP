## 2026-09-18 - Fix Path Traversal in Static File Server
**Vulnerability:** The static file serving logic in `server.js` was vulnerable to path traversal and partial directory match exploits. It used `decodeURIComponent()` on the URL pathname, which decoded `%2E%2E%2F` into `../`. It then used `!filePath.startsWith(PUBLIC_DIR)` for boundary checking. However, because it didn't account for `../` properly (and `startsWith` is vulnerable to partial matches like `public-secret`), attackers could read files outside the designated `public` directory.
**Learning:** Using `startsWith` for path boundary validation in Node.js is insufficient when handling potentially decoded URI components, especially if the base directory path lacks a trailing slash. `decodeURIComponent` turns URL-encoded path separators into active traversal elements.
**Prevention:** Always validate file paths by computing the relative path using `path.relative(BASE_DIR, resolvedPath)` and checking if the relative path escapes the directory (`relativePath === '..' || relativePath.startsWith('..' + path.sep) || path.isAbsolute(relativePath)`). Additionally, return a generic `404 Not Found` rather than `403 Forbidden` to prevent leaking information about the server's internal file structure.
