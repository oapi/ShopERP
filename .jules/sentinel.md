## 2024-05-18 - Fix Path Traversal in Static File Server
**Vulnerability:** The static file server logic in `server.js` was vulnerable to path traversal (reading arbitrary files outside `/public` directory). URL-encoded traversal sequences (like `%2e%2e%2f` for `../`) were decoded via `decodeURIComponent` after Node.js `URL` resolution, bypassing simple `startsWith(PUBLIC_DIR)` boundary checks.
**Learning:** In Node.js native routing, `new URL()` does not normalize URL-encoded path separators. If `decodeURIComponent()` is called afterwards on `url.pathname`, the encoded sequences become active traversal elements (`../`). Using string prefix matching (`startsWith()`) on file paths is insufficient for security if paths are not fully normalized relative to the target directory.
**Prevention:** Always use `path.relative()` and verify that the relative path does not attempt to escape the designated root directory (e.g., does not start with `..` or is an absolute path). Additionally, return generic `404 Not Found` errors for invalid paths to prevent information leakage about the server's directory structure.
