## 2024-05-24 - Node SQLite (node:sqlite) Performance Patterns
**Learning:** In `node:sqlite`, repeatedly calling `db.prepare()` within functions that are invoked iteratively (e.g., in array maps or loops) adds significant performance overhead (often >50%). Moving compilation to module-level hoisted statements resolves this. Furthermore, calculating composite sums via multiple `db.prepare(...).get()` statements can be consolidated into a single query using subselects or conditional aggregation (`SUM(CASE WHEN...)`) to completely eliminate the N+1 overhead and further double the throughput.
**Action:** Always hoist `db.prepare()` when possible. For functions computing multiple independent aggregates like `accountBalance`, `customerBalance`, or `supplierBalance`, use combined queries or `CASE WHEN` aggregation.
